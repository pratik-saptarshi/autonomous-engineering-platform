Domain 1: REQ-01 Dual-Lane Sandboxed Execution Runtime

The platform must govern two distinct execution lanes: high-velocity inner-loop container lanes (Tier 1: Ralph) and strongly isolated, untrusted code pipelines (Tier 2: ESF Factory) with a local-first sandbox hierarchy.

CAP-01 Tier-1 Ralph-Loop Lane Container Orchestration REQ-01.1 · Package: internal/lane

Executes parallel inner-loop code refinement tasks in isolated OCI containers with per-lane git worktrees and zero direct external network egress.

FEAT-01.1 Zero-Egress OCI Container & Worktree Isolation

Spawns ephemeral containers with --network none, read-only rootfs, tmpfs /tmp, virtiofs-mounted git worktree, and mounted IPC socket relays.

TASK-01.1.1 Implement Lane Manager & Container Process Driver LLD T6

Create internal/lane driver managing container spawning, worktree allocation, fence files, and graceful cleanup.

Acceptance Criteria (AC-01.1.1):
  • AC-01.1.1.1 (Network Fence): GIVEN a spawned lane container, WHEN a process inside executes curl https://api.github.com or any network socket call, THEN the OS returns ENETUNREACH or EPERM immediately.
  • AC-01.1.1.2 (Filesystem Immutability): GIVEN a lane container, WHEN a process attempts to write outside /workspace or /tmp, THEN the kernel returns EROFS (Read-only file system).
  • AC-01.1.1.3 (Worktree Boundary): GIVEN lane t1-7f3a9c operating on issue aep-142, WHEN git commands run inside, THEN git mutations occur strictly within $AEP_WORKTREES_ROOT/aep-142 without modifying the parent repository develop worktree.
  • AC-01.1.1.4 (Crash Fence & Reaping): GIVEN a launcher process killed with SIGKILL while the container lives, WHEN aep lane reap runs, THEN it marks the lane active and refuses to reap until the container terminates.

Acceptance Criteria (AC-02.1.1):
  • AC-02.1.1.1 (Local Hierarchy): GIVEN boot on Linux with /dev/kvm, THEN ResolveBackend returns cube-kvm; GIVEN macOS with vz, THEN returns libkrun; GIVEN a host without KVM (Intel N100 or non-bare-metal cloud VM), THEN returns gvisor.
  • AC-02.1.1.2 (Emergency Fallback Restraint): GIVEN BackendRemote, WHEN local backends are operational, THEN BackendRemote is NEVER selected. Remote is selected if and only if all local backends fail AND remote cluster credentials are explicitly configured in factory.toml.
  • AC-02.1.1.3 (Egress Guard): GIVEN factory.toml configured with hardening.acknowledge_open_egress = true, WHEN Doctor or Run is called, THEN execution is rejected with error ErrGovernanceViolation: open egress posture acknowledged.
  • AC-02.1.1.4 (Probe Cryptographic Verification): GIVEN a completed factory pipeline run, WHEN VerifyEgressProbe inspects the VM evidence bundle, THEN it verifies the SHA-256 digest emitted by the in-VM probe. If probe failed or unverified, PR generation is blocked.
