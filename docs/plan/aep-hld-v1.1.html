1. Purpose and scope

This document consolidates the design decisions reached in the working discussion into one reference: how the Autonomous Engineering Platform (AEP) is built and deployed portably, and how it governs two kinds of autonomous execution — fast local ralph-loop lanes and sandboxed ESF (Engineering Software Factory) pipelines — on a shared set of core services.

It is a design, not a record of finished work. Section 9 states exactly what exists in the repository today and what is still to be built; reading the rest of the document as "already implemented" would be wrong.

3. Goals and non-goals

Goals

  • One-command install and run on Linux (x86_64 and ARM64), the Muse 8 GB VM, and macOS (Intel and Apple Silicon).
  • Many parallel lanes under one governance plane with bounded, predictable resource use.
  • Deterministic verification decides success; an agent saying "done" never does.
  • Pluggable sandbox isolation for Tier 2: hardware microVMs via CubeSandbox/libkrun, or user-space kernel sandboxing via gVisor on KVM-free hosts.
  • Fail closed: no autonomous run starts if the environment is unfit.

Non-goals (v1.1)

  • Native Windows binaries or service wrappers.
  • macOS guest VM images (macOS runs the native binary under launchd).
  • Replacing beads or NeuroStrata.
  • Modifying the vendored reference/esf tree (it changes only by re-vendoring).

8. Dispatch and lifecycle

  1. Intake. Work is a beads issue carrying a tier tag (local or factory) and acceptance criteria.
  2. Preflight. aep boot must pass: binaries, NeuroStrata answering, standing guards present, policy blob matches HEAD, memory floor and hardware profile met.
  3. Admission. Dispatcher reserves RAM/CPU for the lane against the active profile budget; if it cannot, the task waits (bounded) rather than oversubscribing.
  4. Execute. Tier 1: claim worktree, start lane container with mounted supervisor socket relays (aep memoryd, aep gwd), run plan/TDD/review/verify. Tier 2: submit factory run with workflow ID esf-beads-<ID>.
  5. Verify. Both lanes emit SHA-256 receipts. For Tier-2 factory work containing untrusted code, independent patch re-verification runs inside a fresh, disposable Tier-2 microVM sandbox with closed egress—never directly on the shared Tier-1 host kernel.
  6. Close. PR merges, bd close, learnings inscribed to NeuroStrata via supervisor relay, lane and reservation released.

9. Governance invariants

  • No lane starts unless aep boot passes (fail closed).
  • All GitHub traffic from lanes goes through ghg via the aep gwd IPC relay. Lane containers hold no GitHub credentials and cannot connect directly to api.github.com.
  • policy.data must equal the committed blob; lanes run with credential-named env vars scrubbed.
  • ESF runs require hardening.acknowledge_open_egress = false (the upstream default), configured closed egress policies (allow_internet = false), and verified in-VM EgressProbe digest. Checking only the acknowledgement boolean is not network enforcement.
  • Tasks requiring Tier-2 isolation MUST NOT be downgraded silently to Tier 1 when Tier 2 / KVM is unavailable; they are strictly quarantined. Downgrade requires an explicit, authenticated operator risk reassessment override (aep dispatch --override-tier1-risk-reassessment).
  • Independent re-verification of Tier-2 patches must execute inside a fresh hardware-isolated microVM sandbox. Tier 1 performs static analysis only (syntax, diff, lint).
  • Model tiering: ralph lanes at standard/measured; frontier/thorough reserved for factory runs.
  • A task has exactly one ledger identity (the beads ID) across both lanes.

10. Implementation status (as of this document)

Built in develop

  • cmd/aep with version, info, boot, verify, supervisor, lock-test.
  • internal/platform/{memory,lock,process} for Linux, macOS and Windows; internal/verifier/runner (allowlist discovery, tail-capped output, SHA-256 receipts, memory preflight, budgets).
  • Makefile targets binaries, vm, oci; scripts/package-vm.sh, scripts/package-oci.sh; Containerfile, docker-compose.yml.
  • Root CI runs gofmt, go vet, go test.

Not yet built

  • aep boot today checks only the memory floor and platform; the NeuroStrata/guard/gh-auth/policy checks still live in scripts/boot-gate.sh.
  • aep supervisor today runs boot gate + one verification pass per tick; it does not dispatch lanes or ESF runs.
  • Lane coordination remains in scripts/lane-coord.sh (Linux flock); no Go lane manager, no admission control, no beads adapter, no dispatcher, no ESF client, no Colima profile or compose topology for the substrate.
  • The "unified verifier inside the CubeSandbox template" and NeuroStrata hooks in the ESF harness are design intent only.

12. Review status & PR #133 review remediations

The v1.1 design incorporates remediations from PR #133 review comments (C1–C5) evaluated under the receiving-code-review, paperthin, overseer, and factchk skills: (1) corrected ESF egress acknowledgement vs probe-verified network boundary; (2) strictly prohibited automatic downgrade to Tier 1, enforcing quarantine for isolation-required tasks; (3) specified supervisor socket relays (aep memoryd and aep gwd) overcoming container loopback and ghg CLI limitations; (4) restricted patch re-verification of untrusted code to disposable microVMs; and (5) formulated a scalable 4-tier profile matrix spanning 2 vCPU / 8 GB (Nano) to 12 vCPU / 48 GB (Workstation).
