AEP Agentic-Container OS — Low-Level Design

Module path: github.com/pratik-saptarshi/autonomous-engineering-platform · Go 1.27.x · stdlib + golang.org/x/sys only unless stated

1. Scope and conventions

This document specifies interfaces, data formats, algorithms and an ordered task list for turning the as-built aep binary into the dispatching, admission-controlled substrate described in the HLD. Every item is marked as-built (exists in develop) or new (to be written). Nothing marked new exists yet.

  • Process boundary rule: lanes are containers; the aep binary on the substrate is the only component that starts, tracks and stops them.
  • All persistent state is JSON written atomically (temp file + rename) under $AEP_STATE_DIR (default ~/.local/state/aep; on Windows %LOCALAPPDATA%\aep), mode 0700.
  • Exit codes: 0 ok · 1 failed check · 2 usage · 3 admission refused · 4 degraded/quarantined · 75 reserved for ghg budget denial (passed through unchanged).

3. As-built components (reference)

Package / commandBehaviour that later work depends on
memory.GetMemoryInfo()Returns MemoryInfo{TotalBytes, AvailableBytes}. Darwin availability is free + speculative pages only, so it under-reports reclaimable memory; admission must not treat it as exact.
lock.New(path)Advisory exclusive lock. TryLock() returns ErrLocked if held. The kernel releases it on process death — the property the lane fence relies on.
process.NewCommand(ctx,name,args,cfg)Returns a ProcessGroup; Kill() terminates the whole tree (group SIGTERM→grace→SIGKILL on POSIX, Job Object on Windows).
runner.RunVerification(ctx,root,minMem,perCmd,budget)Discovers go/cargo/npm/pytest/make checks, runs them sequentially bounded by timeout and budget, stops at first failure, returns VerificationResult{Pass, Receipts[]} with 64 KiB tail hashes.
aep bootMemory probe, 384 MiB floor, platform line, then BOOT-GATE-RESULT: SYSTEM-OK. Does not yet check NeuroStrata, guards, gh auth, binaries or policy.
aep supervisor [--loop --interval D --once]Tick = boot gate then one RunVerification. Boot-gate failure is fatal in every mode; verification failure is fatal only outside loop mode. Ticks never overlap.

4. New packages — interfaces

4.1 internal/profile

type Profile struct {
    Name            string // "workstation-48g", "muse-8g"
    VMCPUs          int    // 12
    VMMemoryMiB     uint64 // 49152
    VMDiskGiB       int    // 220
    SubstrateMiB    uint64 // 8192
    Tier1BudgetMiB  uint64 // 16384
    Tier2BudgetMiB  uint64 // 24576
    Tier1LaneMiB    uint64 // default per-lane reservation, 2048
    Tier2LaneMiB    uint64 // default per-pipeline reservation, 4096
    MaxTier1Lanes   int    // hard ceiling, 10
    MaxTier2Lanes   int    // hard ceiling, 6
    MemFloorMiB     uint64 // 384 (muse) / 512
    ONNXThreads     int
}
func Load(path string) (Profile, error)   // KEY=VALUE file, same keys as hardware-profile.conf
func (p Profile) Validate() error         // sum(substrate+t1+t2) <= VMMemoryMiB; ceilings*laneMiB <= budgets is NOT required (ceilings are upper bounds)

Keys reuse the existing hardware-profile.conf names (AEP_MAX_LANES, AEP_MEM_PREFLIGHT_MB, AEP_ONNX_THREADS) and add AEP_T1_BUDGET_MB, AEP_T2_BUDGET_MB, AEP_T1_LANE_MB, AEP_T2_LANE_MB, AEP_MAX_T2_LANES.

4.2 internal/policy

type Policy struct { EnvScrubFragments []string; SensitivePaths []string; Raw []byte; SHA256 string }
func Load(path string) (Policy, error)
func (p Policy) VerifyAgainstHEAD(repoDir string) error   // git show HEAD:scripts/policy.data | sha256 == p.SHA256
func (p Policy) ScrubEnv(env []string) []string          // drops names containing any fragment, keeping the AUTH boundary exemptions
func (p Policy) CheckWorkingSet(paths []string) error    // refuses sensitive-path matches

Behavioural parity target: scripts/boot-gate.sh check_policy and lane-coord.sh's working-set check. When policy.data is absent, return a distinguishable ErrPolicyInactive so boot can print POLICY-INACTIVE (exit 0) instead of pretending a check passed.

4.3 internal/ledger (beads adapter)

type Issue struct { ID string; Title string; Status string; Tier string /* "local"|"factory"|"" */; Priority int; Labels []string }
type Ledger interface {
    Next(ctx context.Context) (*Issue, error)          // highest-priority open issue with no active lane
    Get(ctx context.Context, id string) (*Issue, error)
    Claim(ctx context.Context, id, owner string) error  // sets in_progress; idempotent for same owner
    Close(ctx context.Context, id, reason string) error
}
func NewBD(binary string) Ledger   // shells out to `bd ... --json`; no direct Dolt access

The adapter only parses bd's JSON output. Tier comes from a label (tier:local / tier:factory); a missing label is treated as local only if the issue also carries risk:low, otherwise dispatch refuses (exit 4) so untrusted work cannot silently land in the weaker lane.

4.4 internal/memoryd (NeuroStrata client)

type Client interface {
    Status(ctx context.Context) error                                   // maps to `neurostrata-mcp status`
    Search(ctx context.Context, ns, query string, k int) ([]Hit, error)
    Inscribe(ctx context.Context, ns string, rec Record) error
    Guards(ctx context.Context) (n int, hasDestructiveRule bool, err error)
}
func NewCLI(binary string) Client   // wraps the neurostrata-mcp CLI, as boot-gate.sh does today

Use the CLI wrapper first (it is what boot-gate.sh verifies today). Do not talk to 127.0.0.1:34343 directly until the daemon's wire protocol is confirmed; the HLD's "HTTP search endpoint" wording is an assumption, not a verified interface.

4.5 internal/admission

type Request struct { LaneID string; Tier int; MemMiB uint64; CPUs float64 }
type Reservation struct { LaneID string; Tier int; MemMiB uint64; CPUs float64; At time.Time }
type Controller struct { /* profile, state file, lock */ }
func (c *Controller) Admit(ctx context.Context, r Request) (Reservation, error)  // ErrNoCapacity on refusal
func (c *Controller) Release(laneID string) error
func (c *Controller) Snapshot() (Usage, error)

State lives in $AEP_STATE_DIR/admission.json, guarded by one lock.FileLock held only for the read-modify-write. See §6 for the algorithm.

4.6 internal/lane

type Manifest struct {
    LaneID, IssueID string
    Tier            int
    Image, Container string
    Worktree        string
    ReservedMiB     uint64
    LauncherPID     int
    StartedAt       time.Time
    State           string // claimed|running|verifying|done|failed|reaped
}
type Runtime interface {                      // docker/podman-compatible CLI driver
    Run(ctx context.Context, spec RunSpec) (containerID string, err error)
    Stop(ctx context.Context, id string, grace time.Duration) error
    Inspect(ctx context.Context, id string) (State, error)
}
func Claim(ctx context.Context, d Deps, issue Issue) (Manifest, error)
func Release(ctx context.Context, d Deps, laneID string, clean bool) error
func Reap(ctx context.Context, d Deps) ([]string, error)   // lanes whose launcher is dead AND container is gone

The fence is a lock.FileLock on lanes/<id>.fence held by the launching aep lane claim --exec process for the lane's lifetime, mirroring lane-coord.sh. A takeover or release --clean requires both: fence free and recorded container no longer running. This reproduces the existing "launcher dead is not worker dead" correctness rule instead of dropping it.

4.7 internal/dispatch

type Decision struct {
    IssueID string
    Tier    int
    Action  string // "run-local" | "run-factory" | "quarantine" | "fallback-local" | "wait"
    Reason  string
}
func Decide(ctx context.Context, d Deps, issue Issue) Decision

Decision table in §7. Decide is pure given its probes, so it is unit-testable with fakes.

4.8 internal/factory

type Client interface {
    Doctor(ctx context.Context) error
    Run(ctx context.Context, req RunRequest) (RunHandle, error)   // WorkflowID = "esf-beads-" + IssueID
    Status(ctx context.Context, id string) (RunStatus, error)
    PatchPath(ctx context.Context, id string) (string, error)
}

Wraps the factory binary's CLI (factory run|status|doctor) rather than importing ESF packages, so the vendored tree stays untouched. A guard reads factory.toml and rejects hardening.acknowledge_open_egress = true before any run.

6. Admission algorithm

Admit(req):
  lock(admission.lock)                         # FileLock.Lock, bounded wait 30s
  s := load(admission.json)
  budget  := profile.TierBudgetMiB(req.Tier)
  used    := sum(s.Reservations[tier == req.Tier].MemMiB)
  ceiling := profile.MaxLanes(req.Tier)
  host    := memory.GetMemoryInfo().AvailableBytes (inside the VM)

  if count(tier) >= ceiling                          -> ErrNoCapacity("lane ceiling")
  if used + req.MemMiB > budget                      -> ErrNoCapacity("tier memory budget")
  if host - req.MemMiB*MiB < profile.MemFloorMiB*MiB -> ErrNoCapacity("host floor")
  append reservation; write atomically; unlock; return
  • Reservations are keyed by lane ID and removed in Release and by Reap; a reservation whose lane manifest is reaped is garbage-collected on the next Admit.
  • The count ceiling and the memory budget are both enforced, because a ceiling alone permits six 6 GB pipelines into a 24 GB budget (HLD §6).
  • Container memory is enforced by the runtime: --memory=<ReservedMiB>m --memory-swap=<same> --cpus=<n>, so a lane exceeding its reservation is OOM-killed inside its own cgroup rather than starving the substrate.
  • CPU is a soft share (not a hard partition): reservations sum may exceed 12 by design; only memory is an admission-blocking resource.

Fallback from factory to local is opt-in per issue. Silently running factory-tagged (untrusted or high-blast-radius) work in the weaker lane would defeat the reason it was tagged.

8.3 Identity conventions

  • Lane ID: t<tier>-<6 hex>. Container name: aep-lane-<laneId>. Worktree: $AEP_WORKTREES_ROOT/<issueId>.
  • ESF workflow ID: esf-beads-<issueId>; a second submit for the same issue is rejected by the dispatcher before calling factory run.
  • Branch: type/scope-short-description and Conventional Commits, per repo AGENTS.md; commit identity per AGENTS.md.

9.2 Substrate compose file (deploy/colima/substrate.compose.yml)

services:
  neurostrata:   # image bakes neurostrata-mcp + pre-seeded model cache; HF_HUB_OFFLINE=1
    volumes: [ns-data:/data]
    mem_limit: 3g
  ghg:           # tools/ghg state in a named volume; one ledger for the whole VM
    volumes: [ghg-state:/state]
    mem_limit: 512m
  aep-supervisor:
    command: ["supervisor","--loop","--dispatch","--interval","2h"]
    depends_on: [neurostrata, ghg]
    volumes: [aep-state:/state, "${AEP_REPO}:/repo:ro"]
    mem_limit: 512m
volumes: { ns-data: {}, ghg-state: {}, aep-state: {} }

Sum of substrate mem_limit values (≈4.0 GB) sits inside the 8 GB substrate budget, leaving headroom for beads/Dolt and the VM's own overhead.

9.3 Lane container run spec

docker run -d --name aep-lane-t1-7f3a9c \
  --memory=2048m --memory-swap=2048m --cpus=1 \
  --read-only --tmpfs /tmp:rw,size=256m \
  --network aep-lanes \                      # reaches ghg + neurostrata only; no direct api.github.com
  -v "<worktree>:/workspace" -w /workspace \
  --env-file <scrubbed.env> \                # produced by policy.ScrubEnv
  aep:1.1 lane-run --issue aep-142
Open point — network egress for lanes. Forcing GitHub traffic through ghg by network design (no direct route) is stronger than relying on lanes to call a shim. Whether the lane image can do useful work (package installs, module downloads) with only ghg and neurostrata reachable depends on the allowlist; this needs a decision before the lane network is locked down.
