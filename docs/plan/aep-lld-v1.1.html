AEP Agentic-Container OS — Low-Level Design

LLD · v1.1 · Status: Proposed · Branch: docs/dual-lane-governance-proposal · Companion: aep-hld-v1.1.html
Module path: github.com/pratik-saptarshi/autonomous-engineering-platform · Go 1.27.x · stdlib + golang.org/x/sys only unless stated

1. Scope and conventions

This document specifies interfaces, data formats, algorithms and an ordered task list for turning the as-built aep binary into the dispatching, admission-controlled substrate described in the HLD. Every item is marked as-built (exists in develop) or new (to be written). Nothing marked new exists yet.

  • Process boundary rule: lanes are containers; the aep binary on the substrate is the only component that starts, tracks and stops them.
  • All persistent state is JSON written atomically (temp file + rename) under $AEP_STATE_DIR (default ~/.local/state/aep; on Windows %LOCALAPPDATA%\aep), mode 0700.
  • Exit codes: 0 ok · 1 failed check · 2 usage · 3 admission refused · 4 degraded/quarantined · 75 reserved for ghg budget denial (passed through unchanged).

3. As-built components (reference)

memory.GetMemoryInfo()Returns MemoryInfo{TotalBytes, AvailableBytes}. Darwin availability is free + speculative pages only, so it under-reports reclaimable memory; admission must not treat it as exact.
lock.New(path)Advisory exclusive lock. TryLock() returns ErrLocked if held. The kernel releases it on process death — the property the lane fence relies on.
process.NewCommand(ctx,name,args,cfg)Returns a ProcessGroup; Kill() terminates the whole tree (group SIGTERM→grace→SIGKILL on POSIX, Job Object on Windows).
runner.RunVerification(ctx,root,minMem,perCmd,budget)Discovers go/cargo/npm/pytest/make checks, runs them sequentially bounded by timeout and budget, stops at first failure, returns VerificationResult{Pass, Receipts[]}. Each CommandReceipt carries full-stream StdoutSha/StderrSha plus 64 KiB display tails; the signed RunReceipt is finalized by the ledger slice.
aep bootMemory probe, 384 MiB floor, platform line, then BOOT-GATE-RESULT: SYSTEM-OK. Does not yet check NeuroStrata, guards, gh auth, binaries or policy.
aep supervisor [--loop --interval D --once]Tick = boot gate then one RunVerification. Boot-gate failure is fatal in every mode; verification failure is fatal only outside loop mode. Ticks never overlap.

Host-family rule: host family selects the runtime; the resolved Backend decides Tier 2. Tier2Supported() is true iff Backend.Usable(); KVMProbe only selects the cube-kvm candidate and is never the capability definition. mac-colima-vz may resolve libkrun without nested KVM; linux-native may resolve gvisor on KVM-free hosts; remote-api counts only when explicitly configured and attested. The nano preset is 2560 + 3584 + 1536 = 7680 MiB (7.5 GiB), with MaxTier1Lanes=1 and MaxTier2Lanes=1. Detect() returns the family from GOOS + runtime probe, then the size tier from CPU/RAM.

6. Admission algorithm

Admit(req):
  lock(admission.lock)                         # FileLock.Lock, bounded wait 30s
  s := load(admission.json)
  if req.Tier == Tier2:
    if !profile.Tier2Supported():
      return ErrTier2Unsupported("no local sandbox backend (Cube/KVM, libkrun, or gVisor) available")
    if err := profile.Tier2Admissible(memory.MiB(req.MemMiB), count(tier)); err != nil:
      return err                                  # capacity, not capability

  budget  := profile.TierBudgetMiB(req.Tier)
  used    := sum(s.Reservations[tier == req.Tier].MemMiB)
  ceiling := profile.MaxLanes(req.Tier)
  host    := memory.GetMemoryInfo().AvailableBytes (inside the VM)

  reqBytes, err := memory.MiB(req.MemMiB).Bytes()
  if err != nil || req.MemMiB == 0                   -> ErrInvalidRequest("invalid memory request")
  if count(tier) >= ceiling                          -> ErrNoCapacity("lane ceiling")
  if used > budget || req.MemMiB > budget - used     -> ErrNoCapacity("tier memory budget")
  if host < reqBytes                                -> ErrNoCapacity("host floor")
  if host - reqBytes < profile.MemFloorMiB*MiB      -> ErrNoCapacity("host floor")
  append reservation; write atomically; unlock; return

The nano preset is 2560 + 3584 + 1536 = 7680 MiB (7.5 GiB); MaxTier1Lanes=1 and MaxTier2Lanes=1. The subtraction is safe only after the host < reqBytes guard; do not reintroduce the unsigned underflow.

  • Reservations are keyed by lane ID and removed in Release and by Reap; a reservation whose lane manifest is reaped is garbage-collected on the next Admit.
  • The count ceiling and the memory budget are both enforced, parameterizing dynamically by the active hardware profile (nano-8g to workstation-48g).
  • Container memory is enforced by the runtime: --memory=<ReservedMiB>m --memory-swap=<same> --cpus=<n>, so a lane exceeding its reservation is OOM-killed inside its own cgroup rather than starving the substrate.
  • CPU is a soft share (not a hard partition): reservations sum may exceed host cores by design; only memory and sandbox backend availability are admission-blocking resources.

9. Runtime topology

9.1 Container and VM runtimes — by host family

mac-colima-vz (macOS): one large shared Colima VM; Docker/Podman containers are spawned on demand inside that VM and bounded by admission control — never one VM per lane. Use --vm-type vz --mount-type virtiofs; worktrees are virtiofs-mounted into the VM. Tier 2 hardware microVMs are supported via Colima nested KVM (requires --nested-virtualization, confirmed 2026-11-09) OR natively via libkrun using Apple's Virtualization.framework (vz) without requiring nested KVM. gVisor is Linux-only; if neither nested KVM nor libkrun is available on macOS, Tier-2 tasks quarantine rather than claiming a local gVisor fallback.

linux-native (Linux): no Colima; Podman (rootless) / Docker runs directly on the host under cgroups v2. Tier-2 hardware microVMs run via cube-kvm if /dev/kvm is present.

linux-gvisor (KVM-Free Linux & Cloud VMs): on hosts lacking /dev/kvm (Intel N100, Raspberry Pi 5, or standard non-bare-metal cloud instances), Tier-2 isolation runs locally via gVisor (runsc in systrap mode). systrap intercepts all guest syscalls in user space with zero hardware virtualization requirement, providing a measured kernel boundary on low-power devices.

Remote Sandbox Cluster (Emergency Last Resort): connecting to an external/remote sandbox cluster (e.g. remote Cube/E2B endpoint) is strictly an emergency fallback of last resort if and only if all local isolation backends (Cube/KVM, libkrun, and gVisor) have failed or are impossible.

Confirmed 2026-11-09 on Apple M3 Max (macOS 27.2, Colima 0.10.3, vz + virtiofs): colima start --nested-virtualization exposes /dev/kvm inside the VM (and in --privileged containers); QEMU accel=kvm is accepted for a nested L2 guest; Docker 29.5.2 containers run in-VM; Temporal (sqlite dev server) serves UI on :8233. Without --nested-virtualization, /dev/kvm is absent — the flag is required. CubeSandbox itself was not installed/tested.

# macOS (M3 Max / Apple Silicon Workstation):
colima start --profile aep \
  --cpu 12 --memory 48 --disk 220 \
  --vm-type vz --mount-type virtiofs --nested-virtualization

# Linux hosts (Intel N100 / AMD Ryzen / Cloud VMs):
# Runs natively on host cgroups v2 using Podman (rootless) or Docker:
aep boot --profile nano-8g --runtime podman

Sandbox backends are probed at boot in order: local KVM -> local libkrun -> local gVisor -> remote fallback. If all options are unavailable, Tier 2 is disabled and untrusted tasks are safely quarantined.

9.2 Substrate compose file (deploy/compose/substrate.compose.yml)

services:
  neurostrata:   # image bakes neurostrata-mcp + pre-seeded model cache; HF_HUB_OFFLINE=1
    volumes: [ns-data:/data]

The substrate supervisor manages four IPC relays in aep-sockets: memory.sock (NeuroStrata), ghg.sock (GitHub), exec.sock (allowlisted command execution), and git.sock (host-side status/diff/commit). All four implement one relay.Handler contract with peer authentication, framing, size caps, and one audit record; they are not four ad-hoc protocols.

9.3 Lane container run spec

docker run -d --name aep-lane-t1-7f3a9c \
  --memory=2048m --memory-swap=2048m --cpus=1 \
  --read-only --tmpfs /tmp:rw,size=256m \
  --network none \                            # no direct network egress
  -v "/run/aep/lanes/t1-7f3a9c:/run/aep:rw" \ # per-lane IPC relays: memory, ghg, exec, git
  -v "<worktree>:/workspace:rw" \
  -v "$AEP_STATE_DIR/empty-git-file:/workspace/.git:ro" \ # mask the linked-worktree gitdir pointer
  --env AEP_EXEC_SOCKET=/run/aep/exec.sock \
  --env AEP_GIT_SOCKET=/run/aep/git.sock \
  --env-file <scrubbed.env> \                 # policy.ScrubEnv; no provider or GitHub tokens
  aep:1.1 lane-exec --issue aep-142
Zero-egress lane architecture. The trusted host harness runs the agent loop and all model inference. A lane is a tool executor: it runs argv-level allowlisted commands over exec.sock, commits over git.sock, and mounts no host .git directory (the linked-worktree .git file is masked). GitHub PATs, provider keys, and loopback ports never enter the container namespace. Dependency caches and package modules are pre-baked into the lane image or mounted via read-only volume cache. Lane output is untrusted tool data; the host harness never interpolates it into a system prompt.
