Plan v2 — Product Roadmap for the Ralph × Warp Self-Improvement Loop

Lane: Self-improvement loop — Ralph × Warp · v2, 2026-11-22 (clean rewrite after planning-wringer panel; v1 superseded) · Method: AEP product-roadmapping skill · Status: for Pratik's checkpoint — R-01 is ruled; R-02…R-08 are open, with recommendations marked PROPOSED — not ruled.

0. Executive takeaway

The roadmap's main reference is the wiring-design Space (warp-self-improving-agents-x-ralph-loop-wiring-design): Ralph is the inner loop; a slower improver iteration over the learnings file is the outer loop; an eval/regression harness and a promotion gate are the two components to build. R-01 is ruled (2026-11-22): instantiate the ralph_loop skill's markdown runtime at ~/workspace/ralph/. The wringer panel (Feasibility: FEASIBLE-WITH-CHANGES; Devil's Advocate: WOUNDED; Risk: three P1s) verified the skeleton and broke three of v1's load-bearing claims, all repaired in this version: (1) the NeuroStrata retrieval every iteration depends on is not performable as the skill prescribes — the client script does not exist and the daemon is down — so C-03 is DEFINED, not VERIFIED, and proving a live search round-trip is Stage A work; (2) the promotion gate's "revert by git" premise was false — neither ~/ nor ~/workspace is a git repository — so rollback machinery must be built, not assumed; (3) the shipped skill already promotes learnings to NeuroStrata ungated, so the gate cannot be sequenced after the behaviour it gates: Stage A's first task is a skill amendment imposing an interim no-inscription rule. This version also adds what v1 lacked entirely: an outcome gate that can fail, and a product kill criterion (§6). The roadmap run is priced as a Trio with numeric budgets (§4); elaboration is depth-graded and round-gated, so the expensive detail is only ever written for the next stage — Stage A's own first iterations double as the spike that retires the design's biggest unknowns.

3. Decision briefs — rulings

Recommendations are PROPOSED — not ruled until Pratik rules. A stage depending on an open ruling is BLOCKED-ON-RULING: feature-level only, no ACs, no gate criteria.

R-01 — Inner-loop substrate — RULED 2026-11-22: (a)

Instantiate the SKILL markdown runtime at ~/workspace/ralph/. Proof obligation carried into Stage A: one dry iteration end-to-end.

R-02 — Improver cadence

  • Options: (a) Weekly cron (Warp's documented pattern). (b) Every N completed inner iterations. (c) Manual until the digest proves itself.
  • Recommendation: PROPOSED (c) for the first two improver cycles, then re-rule with digest-quality evidence. A solo loop's correction feed is thin and self-referential (RPT §12.6); automating the schedule before the signal is proven buys motion, not learning.
  • Cheapest test: two manual improver runs; each must produce ≥1 proposal Pratik would merge, else the feed — not the cadence — is the problem.
  • Blocks: Stage C gate criteria; Stage E entirely (no scheduling assumption is made anywhere in this plan until R-02 lands).

R-03 — Promotion threshold (learnings → long-term memory)

  • Options: recurrence counter reaching 2, 3, or 5 — always plus a green eval run and Pratik's approval.
  • Recommendation: PROPOSED 3, with a discount rule: recurrences attested only by loop-internal roles (which share a base model with the worker — RPT §12.4) count once until a human-originated correction or an independent verifier attestation corroborates. The bare analogy to the 3-failure arbitration constant in v1 is withdrawn as a justification; 3 stands only as a starting value to be re-ruled on real counter distribution.
  • Cheapest test: run Stage A/B with counters instrumented from day one; at the first promotion review, rule the threshold against the observed distribution instead of in the abstract.
  • Blocks: Stage D ACs.

R-04 — Probation and rollback mechanics

  • Ground truth (replaces v1's false premise): memory files are not versioned today (§2). Rollback must be built: git-init ~/workspace/ralph/; a snapshot discipline for ~/MEMORY.md edits; NeuroStrata demotion = a superseding memory per CONN (no delete; global archiving refused).
  • Options: (a) Probation by iterations (flagged for the next 5 inner iterations; recurrence of the addressed failure auto-reverts). (b) Probation by time (2 weeks). (c) No probation; manual revert only.
  • Recommendation: PROPOSED (a), on the built rollback machinery above.
  • Blocks: Stage D ACs. Stage D's gate must include a forced-revert drill against a NeuroStrata inscription, not only against files.

R-05 — Eval harness form

  • Options: (a) Frozen eval-case file, deterministic checks over mined failures. (b) Rubric/LLM-judge scoring. (c) Both, deterministic first.
  • Recommendation: PROPOSED (c) sequenced: (a) ships in Stage B and gates promotion; (b) admitted only where no deterministic check exists, never as sole promotion gate.
  • Cheapest test: seed the harness with the first 3–5 real mined failures from Stage A; if they resist deterministic form, that finding shapes (b).
  • Blocks: Stage B task mapping; Stage D promotion criteria.

R-06 — Home and venue — PROPOSED

Live working copy in ~/workspace/custom-skills/ + ~/workspace/ralph/; durable skill landings in AEP via sync-PR to develop (D4). Roadmap matrix and working papers stay in this lane. Constraint added by the panel: because a live skill edit takes effect immediately, before review (D4), the improver's write surface is a loop-local briefs directory (Warp's companion-skill pattern) — promotion from loop-local briefs into shared custom-skills/ is a separate, explicitly ruled step (see C-06 split, §6).

R-07 — Daemon-contact venue (new, from the panel)

  • Conflict: the narrowed daemon-contact rule (2026-11-05) bars campaign/implementation subagents from touching the live production store during repo work; SKILL mandates a live-store search before every worker spawn and inscription after iterations.
  • Options: (a) Ralph iterations are owner-directed operation, inside the rule's sanctioned route (status check first, sanctioned start, dedupe-search, verify) — the lane's standing practice. (b) Ralph workers are campaign subagents for this purpose; retrieval must be re-routed (e.g., a parent-mediated search the worker never performs directly).
  • Recommendation: PROPOSED (a), with the sanctioned-route steps named in Stage A's retrieval task.
  • Blocks: Stage A retrieval task design.

R-08 — Who may set done (new, from the panel)

  • Conflict: SKILL's roles.md has the Reviewer set done on a pass, then an independent verifier checks afterward; the research's guardrail is verifier-only (RPT §10–§11). Two contradictory status laws.
  • Recommendation: PROPOSED verifier-only: Reviewer moves to in-review; only the independent verifier moves to done. Stage A task 1's skill amendment pins this text.
  • Blocks: Stage A task mapping (small; resolved by the same amendment either way Pratik rules).
Discovered conflict (logged, per Law 1): SKILL's reflect section already instructs ungated promotion — inscribe durable lessons to NeuroStrata "for every iteration that produced a durable lesson," no threshold, no eval, no approval. The promotion gate (C-08) is therefore a skill amendment, not an addition. Until the amendment lands, the interim rule is: learnings.md only; nothing inscribes to NeuroStrata or MEMORY.md from the loop. The amendment is Stage A task 1 and ships via the D4 sync-PR path.

Outcome gate (G-O) and product kill criterion — new in v2. The loop is judged on outcomes, not motion, at the end of Stage C and again at Stage D: G-O passes only if (i) the improver's proposal merge rate over the first two cycles is ≥ 50% (a cycle whose proposals are all rejected is evidence against the loop, not a pass — v1's G-C, which total rejection satisfied, is struck), and (ii) no promoted rule has required revert, and (iii) verifier rejection rate and cost-per-done-task over the Stage C window are no worse than over Stage A's first-3-iteration window (the named reference window the baseline task actually creates — there is no pre-loop verifier, so no pre-loop baseline exists to compare against). Kill criterion: if two consecutive improver cycles produce zero merged proposals, or a promoted rule is cited as the cause of a failure or a stop in any other lane's work, the experiment stops — loop scheduling (if any) is disabled, learnings and briefs are archived, and the lane reports the failure with evidence. That observation, stated in advance, is what "the loop is not working" means.

7. What past learning changed in this plan

  • Substrate and retrieval corrections — the 2026-11-11 correction and the panel's live probes: the runtime doesn't exist (Stage A builds it) and neither does the skill's prescribed NeuroStrata client (Stage A proves a real path).
  • Daemon-contact rule (2026-11-05) — surfaced as R-07 instead of being silently violated by the skill's mandated store access.
  • D4's immediate-effect clause — live skill edits act before review; hence the C-06a/C-06b split and the loop-local write surface, mirroring Warp's companion-skill restriction.
  • NeuroStrata primacy + lesson-entry gate — promotion targets are the primary memory system and its pointer layer; Stage D lands promotions as curator proposals so two writers don't drift MEMORY.md.
  • Review-escape lessons — a defect class with a machine-checked census stops recurring: the eval harness is mined-failure-driven and built (Stage B) before promotion exists (Stage D); G-B's shown-to-bite requirement stands.
  • Planning documents ship with the work — stage outputs that land as AEP PRs carry their plan extract under docs/plans/.
