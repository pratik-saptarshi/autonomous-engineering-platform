OpenShell Patterns — Phase 0 Results

AEP vendored repo maintenance lane · Author: Musebot-Astro · Date: 2026-11-13 · Branch: feat/openshell-patterns-phase0 (unpushed; parent review pending)
Phase 0 of the OpenShell-patterns adoption plan: four pre-registered gate experiments, executed — no feature builds. Evidence artefacts live beside this report in docs/plans/openshell-patterns-phase0/. A killed or unexecutable gate is a successful outcome of this phase, not a failure of the plan.

Executive takeaway

Three gates pass and one could not be executed as specified — and the unexecutable gate carries the phase's most consequential finding. The power-differ (G-P2) passes: it caught all three seeded escalations and, replaying twenty merged PRs, surfaced a real grant human review never mentioned — a bulk skill-sync PR that quietly gave an existing skill a runnable local server. The boot-gate census (G-P6) passes more starkly than the panel predicted: invocation coverage is not partial but zero — no cron, hook, or launcher anywhere invokes the gate. The authority index (G-P11) passes on completeness: building the one-page map surfaced an entire governance layer the unaided view missed (GitHub rulesets) and corrected a stale remembered fact about merge requirements. The ESF credential probe (G-P7) could not be executed as specified because its premise is void here: zero ESF runs have ever executed in this environment — and the executed mechanism probe shows ESF already ships the panel's requested pattern (cube_egress brokered injection), leaving a configuration-enforcement gap instead of a machinery gap. Net effect on the plan: Phases 1, 2b, and 3 proceed; Phase 2a is re-scoped downward; Phase 1 inherits one scope question the evidence raises against its own scoping decision.

G-P2 — Power-differ replay: PASS

Criterion: catch all 3 seeded escalations AND at least 1 real delta human review missed. Method: a throwaway stdlib prototype differ over the policy artefacts AEP diffs by eye (policy.data deny-sets, ghg DEFAULT_LIMITS + classification sets, skills sync scope, skills-tree file sets), replayed over the 20 most recent merged PRs touching a policy-bearing path; mention test = full path, skill name, or bare filename anywhere in the PR's body, reviews, issue comments, or line-level review comments.

  • Seeds 3/3 caught: new ghg bucket (new credentialed host), merge leaving the mutating set (new method), */.config/gcloud leaving the deny-set (metadata reach).
  • Direction and emptiness correct across the replay: grants produce non-empty deltas (#84 +36, #58 +40, #9 +29, #141 +8); the ghg telemetry PR #136 produces an explicit "changed, modelled power unchanged" note; removals (#85, #32) produce denied-only deltas; creations (#40, #43, #83) are reported as creations.
  • The missed delta — PR #58 (bulk skill sync, merged 2026-10-26): 35 of 40 newly-allowed items appear nowhere in the human record. The body aggregates ("39 added") and names one file; the record never mentions the brainstorming skill acquiring scripts/server.cjs and its start/stop scripts, nor executing-plans acquiring executable task scripts. Control: PR #84 scores 0/36 unmentioned — the test is not trivially failed.
  • Universe caveat: the strict artefact subset holds only 9 PRs in the repo's whole history; the sample of 20 requires the skill-content PRs. Results are broken out by tier in the evidence.
Scope observation for Phase 1: within the strict tier, every grant was a creation or was fully enumerated by its author — the catch came from the skills tree, the artefact class the plan's Phase 1 v1 scope defers. As scoped, the Phase 1 build would not have caught the #58 delta. The gate passes on the plan's criteria as written; the Phase 1 scope decision should be re-examined against this evidence before building.

G-P7 — ESF credential probe: COULD-NOT-EXECUTE as specified (premise void)

Criterion: replay a credential from a completed ESF run; pass if any finished-run credential still works or any run was over-scoped. Why it could not run: the inventory leg returns zero — no CubeSandbox deployment, no Temporal, no /dev/kvm, no ESF state or data directories, no containers, and the vendored snapshot ships only cube and fake sandbox providers (the fork's podman provider is not in the pin). No ESF run has ever completed in this environment, so there is no finished-run credential to replay. This is reported as specified-cannot-execute, not redefined.

Substitute mechanism probe (executed): the snapshot's own test suites were run in a scratch copy (Go 1.27.2, sequential): internal/agentharness native-CLI tests, internal/factory credential-policy tests, and the cube provider's network-rule test — all pass. They establish, by execution:

  • environment mode (the legacy default when credential_mode is unset): the run receives the operator's standing provider key verbatim in its environment; a grep for rotation/revocation/expiry across the credential path returns zero hits — post-run replay would succeed by construction, and the key's scope is the whole provider account, broader than any run needs.
  • cube_egress mode: the run receives only the literal placeholder cube-egress-managed-placeholder; the secret is resolved worker-side and injected by CubeEgress into exact scheme/host/method/path matches. Nothing exists to replay.
Premise correction for Phase 2a: the panel priced P7 as a build (per-run scoped credentials on ghg's lease machinery). The snapshot already contains the pattern — brokered, endpoint-scoped injection — as cube_egress. The residual gap is that environment mode exists and is the default. The AEP-shaped remainder is configuration enforcement (mandate cube_egress; refuse or alarm on environment), not new machinery — and it is dormant until an ESF-capable host exists, since cube_egress requires the Cube provider that cannot run in this VM.

G-P6 — Launch-path census: PASS

Criterion: pass if any autonomous launch path does not invoke boot-gate.sh; kill if coverage is already 100%. Result: coverage is 0%. The complete census (52 live schedules incl. system jobs, 61 on-disk definitions, 1 hook, and the lane-coordinator, orchestrator, and daemon-lifecycle launcher classes) finds no invocation anywhere; the only executions of the gate are its own self-tests and lane-coord's test fixtures. Lane claims carry a partial substitute — lane-coord hash-binds policy.data at claim time — covering the gate's policy check only, and only on that one path. The panel expected an unwired fraction; the executed census finds the wiring entirely absent, so Phase 2b's work is wiring design, not gap-hunting, and should compose with lane-coord's existing binding rather than duplicate it.

G-P11 — Authority index: PASS (completeness leg)

Criterion: pass if the hand-built page measurably cuts answer time OR catches a surface the unaided answer missed. Time leg: recorded as not demonstrated — an expert tester's unaided verification lookups run 0.0–3s, a floor the page cannot beat; measured in operations, unaided answers need 2–4 sources per question, aided need 1. Completeness leg (decisive):

  • Ruleset layer caught: branch governance is split between classic protection and two active rulesets on the default branch carrying deletion/force-push blocks, a CodeQL merge gate, a code-quality gate, strict status checks, and linear history. The unaided list named only "branch protection".
  • Stale fact corrected: lane records from 2026-11-09 state develop requires 1 approving review; at extraction, neither branch's protection contains a review requirement. The index reads the current surface, not the remembered one.
  • Omitted surface added: 13 SkillSpector baseline files gate skill changes and were absent from the unaided list; conversely CODEOWNERS proves to be a single effective rule line.
  • Generation feasibility: 11 of 15 index rows are fully generatable from an API or parseable file; 3 are generatable with a pointer component; 2 (procedural standing rules, runtime permission/guard state) are pointer-only by nature. The Phase 3 generator is feasible as priced.
