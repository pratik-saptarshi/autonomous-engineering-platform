Plan — bake bd metrics OFF into environment onboarding

Decision (Pratik, 2026-11-17, verbatim): "my preferred method are 1+2+3, do all 3 and open a PR for AEP." All three layers land in this PR. Target branch: develop (AEP branch model). Merge remains Pratik's per-PR call.

Background

The bd CLI (Beads v1.3.1) collects anonymous command-usage metrics on by default (opt-out). Each event carries only the command name + bd version + OS, keyed by a machine-derived HMAC ID (no issue content, paths, remotes, or typed text — official Beads FAQ). Events queue in ~/.beads/eventsData/*.evtq and POST to https://gastownhall-eventsapi.com/mp/collect. On the current VM it ran unnoticed from install day (2026-10-13) until spotted on 2026-11-17; it has been turned off there and logged in ~/workspace/outbound-access-date.log. This PR makes OFF the default for every future environment built from AEP's onboarding runbook (docs/runbook.md, "Runbook — reproducing the environment").

The off state persists in ~/.config/bd/config.yaml, exactly as bd metrics off writes it (this location/format is v1.3.1 behavior — pinned as a note in the runbook text):

metrics:
    disabled: true
    endpoint: https://gastownhall-eventsapi.com/mp/collect
    notice_shown: true

Global constraints

  • Single file changes behaviour: docs/runbook.md only (plus this plan). No scripts, no CI changes.
  • Ordering is the substance of Layer 1: the pre-seed must land before the first bd invocation of any kind — in the current runbook that is bd --version immediately after install. Events are captured from the first command, so a seed placed after install-but-before-use is already too late if any bd command ran.
  • Idempotence: running the onboarding steps twice must end in the same state as once (the pre-seed writes identical content; bd metrics off is idempotent). A run interrupted after the pre-seed but before install leaves metrics off — strictly safer than the reverse order, and re-running completes cleanly.
  • Conventional Commit subjects; author Musebot-Astro; GitHub calls via ghg only.
