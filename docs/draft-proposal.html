1. Executive Summary & Vision

In version 1.1, the Autonomous Engineering Platform (AEP) evolves from a script-based runner into an Agentic-Container Operating Substrate. AEP provides the durable, shared host foundation hosting five essential platform services. Above this foundation, AEP orchestrates and capacity-bounds parallel, ephemeral container execution lanes divided into two operational tiers:

  • Tier 1: Ralph-Loop Lanes — High-velocity, parallel inner-loop containers (8–10 concurrent lanes) for continuous feature engineering, TDD, and local pull requests.
  • Tier 2: ESF Factory Pipelines — Heavily isolated, sandboxed outer-factory containers (4–6 concurrent pipelines) backed by Temporal durable workflows and CubeSandbox microVMs for untrusted code, CVE analysis, and high-blast-radius refactoring.

Core Runtime Services (AEP Substrate)

  • NeuroStrata: Long-term memory engine running on loopback, pre-seeded embedding cache (523MB), and ladybug.db store.
  • Unified Ledger: beads issue tracker keyed as the single source of truth; avoids orphan factory runs.
  • Rate Limiter (ghg): Coalesces multi-agent run watching and enforces rate caps across all containers.
  • Policy & Boot: Git-verified policy.data prevents uninspected runtime mutation; aep boot gates starts.

Tier 1: Parallel Ralph Lanes

  • 8–10 Parallel Containers: Each lane binds to an isolated Git worktree mounted from the host filesystem.
  • Near-Zero Latency: Uses virtiofs for shared file events; instant host IDE reflection in T3 Code, Herdr, or Orca.
  • Verification Receipts: Runs aep verify locally in container, producing hash-chained execution proofs.

Tier 2: Parallel ESF Pipelines

  • 4–6 Parallel Factory Runs: Dispatched via Temporal durable workflows when tasks require hardware sandboxing.
  • MicroVM Isolation: Dispatches agents inside disposable CubeSandbox microVMs with strict measured egress (ADR 0007).
  • Patch Ledger: Generates tamper-proof diff patches, token expenditure records, and verified test proofs.

4. Dual-Lane Dispatch & Execution Lifecycle

  1. Task Ingestion: Tasks enter beads backlog tagged with risk metadata: tier: local (Ralph) or tier: factory (ESF).
  2. Fail-Closed Preflight: The AEP supervisor runs aep boot, confirming NeuroStrata, policy checksums, and available memory headroom.
  3. Lane Allocation:
    • Tier 1: aep lane claim allocates an isolated worktree and spawns a Ralph OCI container running TDD iterations.
    • Tier 2: AEP invokes factory run via Temporal; ESF spins up a fresh Cube microVM, injects the prompt over stdin, and runs deterministic in-VM gates.
  4. Receipt & Patch Consolidation: Both lanes emit cryptographic receipts (SHA-256 tail digests). ESF patches are verified by Ralph in a clean lane before PR generation.
  5. Cognitive Inscription: Root causes, fixes, and edge cases are inscribed into the host NeuroStrata instance via loopback, immediately benefiting subsequent tasks across both tiers.

5. Adversarial Assessment Panel (Paperthin Audit v1.1)

[hate] Root Objection & Resolution (v1.1)

Previous Objection: Unmanaged dependency on non-existent Temporal/Cube clusters would freeze autonomous execution.

v1.1 Resolution: AEP substrate enforces an Automated Graceful Degradation Gateway in aep dispatch: if the Temporal cluster or Cube daemon is offline, factory-tagged tasks are quarantined with an explicit diagnostic alert or downgraded to a fenced Ralph worktree with elevated review gates, preventing autonomous deadlocks.

[ssotize] Single Task Ledger

Enforcement: beads issue IDs are the single canonical foreign key. Temporal workflow IDs must match esf-beads-<ID> to prevent state divergence.

[modelchk] Cognitive Tiering

Enforcement: Ralph containers are pinned to standard model tier with measured effort. High-cost frontier models with thorough reasoning are reserved for sandboxed factory runs.

[detool & debloat] Unified Verifier

Enforcement: Compiled Go binary aep verify is baked into both the Ralph OCI container and the CubeSandbox template, eliminating duplicated test-running logic.

[factchk] Real Disk Headroom

Enforcement: 220 GB disk allocation safely accommodates 50GB model/cache footprints, 10 concurrent git worktrees (3–5GB each), and 6 ephemeral microVM disk overlays simultaneously.

6. Final Panel Verdict

Verdict: FULL APPROVAL (v1.1)

Version 1.1 resolves the load-bearing root objections identified in the initial adversarial audit. The 12-CPU / 48GB-RAM / 220GB-Disk allocation provides generous, balanced headroom for running the AEP Substrate alongside 8–10 Ralph lanes and 4–6 ESF pipelines concurrently.
