Version: v1.1 Revised Profile: 12 CPU · 48GB · 220GB Pattern: Agentic-Container OS Panel: Paperthin Validated

1. Executive Summary & Vision

In version 1.1, the Autonomous Engineering Platform (AEP) evolves from a script-based runner into an Agentic-Container Operating Substrate. AEP provides the durable, shared host foundation hosting five essential platform services. Above this foundation, AEP orchestrates and capacity-bounds parallel, ephemeral container execution lanes divided into two operational tiers:

  • Tier 1: Ralph-Loop Lanes — High-velocity, parallel inner-loop containers (8–10 concurrent lanes) for continuous feature engineering, TDD, and local pull requests.
  • Tier 2: ESF Factory Pipelines — Heavily isolated, sandboxed outer-factory containers (4–6 concurrent pipelines) backed by Temporal durable workflows and CubeSandbox microVMs for untrusted code, CVE analysis, and high-blast-radius refactoring.

Core Runtime Services (AEP Substrate)

  • NeuroStrata: Long-term memory engine running on host loopback (`127.0.0.1:34343`), accessed from lanes via host-mediated UNIX domain socket relay (`aep memoryd`) or vsock.
  • Unified Ledger: beads issue tracker keyed as the single source of truth; avoids orphan factory runs.
  • Rate Limiter Relay (ghg): aep gwd IPC daemon proxies lane requests to host `tools/ghg/bin/ghg`, preserving rate caps and coalesced pollers without exposing credentials.
  • Policy & Boot: Git-verified policy.data prevents uninspected runtime mutation; aep boot gates starts.

Tier 1: Parallel Ralph Lanes

  • 8–10 Parallel Containers: Each lane binds to an isolated Git worktree mounted from the host filesystem.
  • Near-Zero Latency: Uses virtiofs for shared file events; instant host IDE reflection in T3 Code, Herdr, or Orca.
  • Verification Receipts: Runs aep verify locally in container, producing hash-chained execution proofs.

Tier 2: Parallel ESF Pipelines

  • 4–6 Parallel Factory Runs: Dispatched via Temporal durable workflows when tasks require hardware sandboxing.
  • MicroVM Isolation: Dispatches agents inside disposable CubeSandbox microVMs with strict measured egress (ADR 0007).
  • Patch Ledger: Generates tamper-proof diff patches, token expenditure records, and verified test proofs.

Runtime Profile Auto-Detection

aep profile detect returns {host_os, host_family, size_tier, container_runtime, kvm_available, recommended_profile}. On macOS it selects mac-colima-vz (Tier 2 off); on Linux with /dev/kvm it selects linux-native (Tier 2 on). If virtualization is absent, Tier 2 is disabled and tier:factory tasks quarantine — never downgrade. 

# macOS / mac-colima-vz — ONE shared large VM, containers spawned on demand inside it:
colima start --profile aep --cpu 12 --memory 48 --disk 220 --vm-type vz --mount-type virtiofs
# (smaller Macs scale down, e.g. --cpu 8 --memory 32 --disk 150; same single-VM model)

# Linux / linux-native — no Colima; Podman/Docker on host, KVM probed for Tier 2:
aep boot --profile linux-native-8g --runtime podman   # or -16g / -32g / -48g by size tier

4. Dual-Lane Dispatch & Execution Lifecycle

  1. Task Ingestion: Tasks enter beads backlog tagged with risk metadata: tier: local (Ralph) or tier: factory (ESF).
  2. Fail-Closed Preflight: The AEP supervisor runs aep boot, confirming NeuroStrata, policy checksums, hardware profile detection, and available memory headroom.
  3. Lane Allocation & Mediation:
    • Tier 1: aep lane claim allocates an isolated worktree and spawns a Ralph OCI container running TDD iterations with mounted supervisor socket relays for NeuroStrata (aep memoryd) and GitHub (aep gwd).
    • Tier 2: AEP invokes factory run via Temporal; ESF spins up a fresh Cube microVM, injects the prompt over stdin, validates closed egress via in-VM EgressProbe, and runs deterministic in-VM gates.
  4. Receipt & Isolated Patch Re-Verification: Both lanes emit cryptographic receipts (SHA-256 tail digests). For Tier-2 factory work containing untrusted code, independent patch re-verification (running repo tests via aep verify) executes inside a fresh, disposable Tier-2 microVM sandbox with closed egress—never directly on the shared Tier-1 host kernel.
  5. Supervisor-Mediated Cognitive Inscription: Root causes, fixes, and edge cases are inscribed into host NeuroStrata via supervisor relay sockets (Tier 1) or vsock outbox spool (Tier 2), ensuring guest loopback isolation does not block cross-tier memory updates.

5. Adversarial Assessment Panel (Agentic Skills Audit & PR #133 Review Remediations)

[hate & receiving-code-review] Isolation Preservation & Quarantine Policy

PR Review Finding (C2): Automatic downgrade of Tier-2 tasks to Tier 1 when ESF/Cube is unavailable removes the hardware microVM sandbox boundary that justified Tier-2 routing. Elevated review gates cannot prevent malware or exploit payloads that execute during test runs.

Remediation: When Temporal, Cube, or KVM is unavailable, tasks tagged tier:factory are strictly QUARANTINED (status quarantined_esf_unavailable or quarantined_unsupported_tier2). Automatic downgrade to Tier 1 is strictly forbidden. Downgrade to Tier 1 requires an explicit, authenticated operator risk reassessment override (aep dispatch --override-tier1-risk-reassessment --reason="...").

[factchk] Egress Acknowledgement vs Network Enforcement

PR Finding (C1): In reference/esf, AcknowledgeOpenEgress defaults to false. Setting it to true acknowledges open risk; it does not enforce security. Checking only that flag does not establish measured egress.

Enforcement: AEP requires AcknowledgeOpenEgress = false, an explicit closed policy (allow_internet = false), and verifies the SHA-256 digest of the in-VM EgressProbe before accepting run evidence.

[ssotize] Host Relays for Container Isolation

PR Finding (C3 & C5): Guest loopback 127.0.0.1:34343 does not reach host NeuroStrata, and tools/ghg is a CLI without a network daemon.

Enforcement: AEP provides host-side supervisor relays: aep memoryd (proxying IPC sockets to host NeuroStrata) and aep gwd (proxying lane GitHub CLI calls to ghg.py, keeping PAT tokens out of containers).

[hate] Sandboxed Re-Verification

PR Finding (C4): Running repository test commands (npm test, cargo test) on untrusted Tier-2 patches inside Tier 1 executes hostile code on the shared host.

Enforcement: Dynamic re-verification of Tier-2 patches must execute inside a fresh, disposable Tier-2 microVM. Tier 1 performs static checks only (AST syntax, diff inspection).

[modelchk] Scalable Profiles

Capacity Matrix: Hardware-profiled admission controller scales memory budgets from Nano (2 vCPU / 8 GB, 1–2 Ralph lanes, Tier 2 disabled) up to Workstation (12 vCPU / 48 GB, 8–10 lanes, 4–6 microVMs).

6. Final Panel Verdict

Verdict: REMEDIATED & VALIDATED (v1.1)

Version 1.1 fully incorporates the PR #133 review findings and agentic skills audit. Host-mediated socket relays bridge isolated containers to substrate services without exposing loopback or credentials; untrusted work is quarantined rather than downgraded when hardware virtualization is absent; and admission control scales dynamically from 2 vCPU / 8 GB edge nodes up to 12 vCPU / 48 GB workstations.
