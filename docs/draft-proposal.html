AEP Dual-Lane Governance Architecture

Formal Technical Design Proposal for Co-Governing ralph-loop and ESF (Engineering Software Factory) under Autonomous Engineering Platform Control.

Status: Proposed Draft Architecture: Dual-Lane Tiered Execution Review: Paperthin Adversarial Audit

1. Executive Summary & Objective

The Autonomous Engineering Platform (AEP) currently implements a periodic autonomous loop (ralph-loop) that operates directly on host Git worktrees, alongside a vendored reference implementation of the Engineering Software Factory (reference/esf) designed for microVM-isolated execution.

This proposal specifies the formal architecture to integrate both engines into a Dual-Lane Unified Governance Framework. It provides a single source of truth for task routing, policy enforcement, cognitive memory sharing, and deterministic verification, preventing divergence while maximizing development velocity and execution safety.

2. System Topology & Dual-Lane Model

+---------------------------------------------------------------------------------------------------+ | AEP UNIFIED GOVERNANCE PLANE | | - aep boot / boot-gate (Fail-Closed Preflight) - policy.data (Git-Bound Policy & Scrub) | | - NeuroStrata Cognitive Memory (ladybug.db) - ghg Gateway (Capped GitHub Poller) | +-------------------------------------------------+-------------------------------------------------+ | [ Task Dispatcher & Risk Assessment ] | +----------------------------+----------------------------+ | | v (Tier 1: Local / Standard) v (Tier 2: High-Risk / Sandboxed) +------------------------------------------+ +------------------------------------------+ | RALPH-LOOP (INNER LOOP) | | ESF FACTORY (OUTER LANE) | | * Isolation: Git Worktree + flock | | * Isolation: CubeSandbox MicroVM | | * Cadence: Periodic 2-Hour Autonomous | | * Cadence: Event-Driven Temporal Run | | * Engine: Subagent-Driven TDD | | * Engine: OpenCode / Claude Code / Pi | | * Gate: mechanical_verify.py | | * Gate: Deterministic In-VM build.sh | | * Output: Direct Working-Tree Branch | | * Output: Cryptographic Patch + Evidence| +--------------------+---------------------+ +--------------------+---------------------+ | | +----------------------------+---------------------------+ | v [ Inscription & Verification: NeuroStrata & Pull Request ]

Tier 1: Ralph-Loop (Fast Inner Lane)

  • Work Scope: Day-to-day feature work, bug fixes, refactoring, test additions, and documentation.
  • Isolation: Host Git worktrees isolated by scripts/lane-coord.sh using descriptor-bound file locks and process group isolation.
  • Cadence: 2-hour scheduler (cron / aep supervisor) bounded to at most 6 task iterations.
  • Verification: mechanical_verify.py allowlist test discovery with 64KB tail-capped outputs and SHA-256 receipts.

Tier 2: ESF Factory (Sandboxed Outer Lane)

  • Work Scope: High-risk tasks, untrusted dependencies, multi-repo changes, security spikes, and large migrations.
  • Isolation: Hardware-isolated CubeSandbox microVMs; destroyed unconditionally on every exit path.
  • Cadence: Asynchronous execution orchestrated by Temporal durable workflows.
  • Verification: Deterministic in-VM verification gates (build.sh, test.sh) evaluated strictly by exit code.

4. Hand-off & Interoperability Protocol

  1. Task Tagging: Issues in backlog.md or beads carry an explicit tier annotation (execution_tier: local vs execution_tier: factory).
  2. Delegated Dispatch: If Ralph encounters a task flagged for factory execution, it invokes: 
    factory run --repo <REPO_URL> --rev <SHA> --task "<DESCRIPTION>" --agent opencode2 --verification default
  3. Sandboxed Execution & Evidence: ESF runs the agent inside a Cube microVM, runs deterministic gates, and exports patch.diff, run.json, and verification logs to internal/artifacts.
  4. Patch Verification & Inscription: Ralph ingests the generated patch into a local Git worktree, runs aep verify, opens the PR, and inscribes durable findings into NeuroStrata memory.

5. Adversarial Assessment Panel (Paperthin Skills Audit)

A formal adversarial assessment was conducted using the repository's vendored Paperthin Methodology (skills/hate, skills/modelchk, skills/factchk, skills/ssotize, skills/detool, skills/debloat).

[hate] Single Load-Bearing Root Objection

Root Objection: The proposal treats the bridge between Ralph (local single-process shell/worktree) and ESF (distributed Temporal/Cube cluster) as a light procedural handoff, ignoring that CubeSandbox and Temporal require heavyweight external infrastructure that does not exist on local developer machines or the 8GB Muse VM. If the factory lane requires external servers to run, Ralph delegating to it either hangs indefinitely or fails closed on 100% of factory-tagged tasks.

The First Nail (Cheapest Falsification): Run factory doctor against an unconfigured local machine. It immediately fails on missing Temporal and Cube endpoints. A single task tagged execution_tier: factory in an unmanaged environment will freeze the autonomous loop.

[ssotize] Single Source of Truth

Finding: Dual backlogs create state drift. If ESF tracks work via Temporal Changes and PostgreSQL, while Ralph tracks work via backlog.md and beads, status synchronization will inevitably desynchronize.

Mitigation: Enforce beads as the sole canonical source of truth for work items. ESF runs must be keyed directly to the beads issue ID.

[modelchk] Cognitive Budget & Sizing

Finding: Running high-reasoning frontier models inside both Ralph subagents and ESF microVM workers simultaneously will exhaust rate limits and GPU/API budgets.

Mitigation: Bind Ralph planning to standard tier with measured reasoning effort. Reserve frontier tier with thorough reasoning exclusively for microVM factory runs.

[factchk] Reality-Grounded Verification

Finding: The proposal asserts that acknowledged_open_egress = false guarantees network closure. Fact check: In ESF, fresh installs default to true and bypass egress restrictions unless explicitly overridden in factory.toml.

Mitigation: Add an assertive check in aep boot that exits with error code 1 if factory.toml has hardening.acknowledge_open_egress = true.

[detool & debloat] Redundancy Removal

Finding: Both Ralph (via mechanical_verify.py) and ESF (via internal/verification) implement separate test runners, log tail buffers, and receipt collectors.

Mitigation: Port ESF's verification harness to invoke the unified aep verify binary inside the microVM, eliminating duplicated verification codebases.

6. Panel Verdict & Implementation Directives

Panel Verdict: CONDITIONAL APPROVAL

The Dual-Lane architecture is sound in principle, but must implement the following three non-negotiable mitigations before production activation:

  1. Graceful Degradation Fallback: If Temporal or CubeSandbox is unreachable, aep dispatch must refuse to stall; it must either fail closed with an explicit diagnostic or fall back to an isolated worktree lane with an escalated confirmation prompt.
  2. Single Issue State Ledger: Key all Temporal workflows directly to beads issue IDs; never allow ESF to create orphan changes untracked by the platform backlog.
  3. Shared Unified Verifier: Compile aep verify as a standalone static binary and bake it into the CubeSandbox base image so verification rules are identical in both lanes.
