## design_critic — 1 Blocker, 10 Majors, 2 Nits (13)

### [Issue 1] [design_critic-4-1] — Blocker — §6 (L88), §8 D6 (L210), §12 (L424): read-only guarantee is false by the doc's own admission
The core EGM guarantee — Goldfish reviewers are read-only — is false, and the stated control neither prevents a write nor fully rolls one back. D6: "Detection is post-hoc: the snapshot diff detects a write after it happens; it does not prevent it. The round is fail-closed … the filesystem is not — the residual write-before-detection risk stands." Memory/DB paths are explicitly out of snapshot scope ("no snapshot is taken of the NeuroStrata store … silent memory use is undetectable"). Rollback is `git checkout -- <paths>`, which restores tracked-file content only: it cannot restore a deleted untracked file, remove a newly created untracked file, or undo a memory/DB write. §6 lists this as mitigated by "read-only briefs + post-run snapshot diff (detection only) + line-existence check" — a brief is an instruction to a model, not a tool restriction, and line-existence checks say nothing about writes. A standard requires risks to be identified *and mitigated*; here the principal risk is accepted as a residual while reviewers run with full filesystem/memory access in parallel. Recommendation: add a real containment control (separate worktree/copy, read-only bind/filesystem, or a harness that actually restricts tools) or narrow the pilot to targets whose corruption is fully recoverable from git; at minimum, make rollback handle untracked creation/deletion and state explicitly that memory/DB writes are unrecoverable.

### [Issue 2] [design_critic-4-2] — Major — §6 (L91), §10.4 (L357), §14 decision 6 (L437): no enforceable token or dollar budget
Only a spawn/time bound ("at most 5 rounds × 5 reviewers = 25 spawns … interim budget 12.5 reviewer-hours per run; token budget set by §14 decision 6 from the pilot log's actuals"). §10.4 adds "Phase 1 interim default: the pilot's 30-minute timeout and the pilot log's token actuals carry forward; §14 decision 6 may tighten them before Phase 1, but Phase 1 does not wait on it." No per-reviewer token estimate, no dollar figure, no cap on target-document size, no maximum total cost per run. A "25 spawns" bound is not a cost bound: each spawn reads the persona, the standard(s), and the full target, so token cost scales with target size, which is unbounded. Recommendation: set an interim token cap (per-reviewer and per-run maxima, plus a maximum target size or truncation rule) now, with decision 6 tightening — not creating — it.
