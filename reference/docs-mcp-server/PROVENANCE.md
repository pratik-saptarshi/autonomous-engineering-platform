## Updating this snapshot

This tree changes only by re-vendoring: replace it wholesale with a new pinned upstream snapshot and regenerate `.github/vendor-docs-mcp-server.sha256` in the same change. Code or dependency edits made in place — including dependency-update PRs against this tree — are closed, not merged: a merged bump would leave the tree matching no upstream commit and falsify the provenance pinned above.

Branch note: the fork's default branch is `develop` (created for this vendoring, per the fork-first pattern used for the NeuroStrata and ESF forks), while upstream's default is `main`. The fork's `main` is a pristine upstream mirror — upstream updates are pulled in there (`gh repo sync --branch main`) and merged forward into `develop`, where the fork's own incremental changes live. At the first snapshot (2026-10-31) `develop` was identical to upstream `main` at `4e35baa`. This re-vendor's pin is no longer identical to upstream: on top of upstream `main` at `aa8b5b7` (two upstream commits past `4e35baa`, including the husky commit-msg fix), `develop` carries the fork's security-baseline commits from the AEP vendored-repo maintenance pilot (2026-11-07): a Dependabot config and a CI trigger fix (fork PR #3), and the first fork-first alert fixes (fork PR #4) — follow-redirects 1.16.1 → 1.16.2 (GHSA-mrwp-f3q8-3g9p), a stale lockfile root version repaired (3.3.0 → 3.4.1), and vitest `^4.1.12` → `^5.1.0`.
